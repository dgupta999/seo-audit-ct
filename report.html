Crawlability Audit

What affects Googlebot's ability to discover, parse, and understand the page

🔴 No Hreflang — Zero Regional Targeting

Critical

Cleartrip has zero hreflang tags. This is not just a missed opportunity — it actively means Google cannot understand which regional users this page serves. India has 900M+ internet users across multiple languages. NRIs in the UAE, UK, and US search for Mumbai-Delhi flights regularly.

MakeMyTrip does this

<link rel="alternate" hreflang="en" href="...airtickets.html">
<link rel="alternate" hreflang="hi" href=".../hi/...airtickets.html">
Has a full Hindi version of the page — captures 500M+ Hindi speakers

EaseMyTrip does this (5 regions)

hreflang="x-default", hreflang="en-in", hreflang="en-ae", hreflang="en-gb", hreflang="en-th"
Explicitly signals NRI audiences in UAE, UK, Thailand

CT fix: Add minimum hreflang="en-in" + hreflang="x-default". Long-term: build Hindi version.

🟠 Robots Meta Uppercase — Non-Standard

Low Risk / Fix Anyway

CT's robots tag reads content="INDEX,FOLLOW" — uppercase. Technically Google parses this correctly but it's non-standard per spec (RFC 5234). Every single competitor uses lowercase index, follow. More importantly, CT was earlier flagged as having no robots meta — it exists but is inconsistently applied across the site, suggesting template issues.

All 4 competitors

<meta name="robots" content="index, follow">

CT fix: Standardise to lowercase index, follow across all flight schedule pages.

🟠 CDN Resource Hints Missing

High

CT has preconnect for Google Fonts and its own CDN (seoui.cltpstatic.com). But it's missing dns-prefetch for its CDN domains — a cheap, widely-supported hint that reduces DNS lookup latency for sub-resources. MakeMyTrip explicitly dns-prefetches all 3 of its CDN domains before the browser needs them.

MakeMyTrip's CDN strategy

<link rel="dns-prefetch" href="//cssak.mmtcdn.com">
<link rel="dns-prefetch" href="//jsak.mmtcdn.com">
<link rel="dns-prefetch" href="//imgak.mmtcdn.com">
+ preload as="script" for critical JS bundle

CT fix: Add dns-prefetch for cltpstatic.com and any image CDN. Add preload as="script" for the critical JS bundle.

🔴 Images: 20 Missing Alt + Multiple "placeholder" Alt Values

Critical

CT has two image alt problems: (1) 20 images with no alt attribute at all. (2) Multiple content images with alt="placeholder" — this is worse than missing alt. Googlebot reads "placeholder" as the image description and indexes it as such. It actively misdescribes the image.

CT actual HTML — bad alt text

<img src="...price.webp" alt='placeholder' fetchpriority="high"/>
<img src="...prefered-airline-.webp" alt="placeholder" fetchpriority="high">
<img src="...duration_image.webp" alt="placeholder">
These are content images (price chart, airline preference, duration) with "placeholder" as their alt.

Competitors

MakeMyTrip: 0/1 missing · Goibibo: 0/1 missing · Ixigo: 0/211 missing (100% coverage) · EaseMyTrip: 29/180 missing (16%)

CT fix: Replace all alt="placeholder" with descriptive text (e.g., "Mumbai to Delhi flight price chart", "Preferred airlines for Mumbai Delhi route"). Then fix the 20 fully missing alt attributes.

🟠 OG Tags Completely Absent

Critical for Social

CT has no og:title, og:description, or og:image. In India, WhatsApp is the #1 link-sharing channel. When someone shares CT's Mumbai-Delhi page on WhatsApp, it renders as a broken card — no image, no preview text. Every competitor has OG tags. This is a zero-cost fix that directly impacts referral traffic and brand perception.

og:image: branded logo with deal messaging

Google Quality Rater Guidelines — Applied Analysis

QRG directly informs how Google's algorithms score pages. This is YMYL content (travel, money). The bar is higher.

YMYL Classification: This page handles financial decisions

Flight booking pages are YMYL (Your Money or Your Life) — a category where Google explicitly demands higher EEAT signals. A user booking a ₹7,000 flight based on wrong information suffers real financial harm. QRG rates YMYL pages on: accuracy, freshness, expertise, trustworthiness. Every gap below is amplified under YMYL scoring.

CT-Specific Findings from HTML Audit

Issues found only in CT's page that no competitor has — unique technical debt

Dual Schema Format — JSON-LD + Microdata Conflict

High

CT uses both JSON-LD structured data AND HTML Microdata on the same page. The head contains <meta itemprop="name"> and <meta itemprop="description"> — Microdata format. The body contains JSON-LD schemas. Running two formats simultaneously can confuse Google's parser and result in schema validation errors in Search Console. All competitors use JSON-LD only.

CT head — Microdata (redundant)

<meta itemprop="name" content="Mumbai (BOM) to Delhi (DEL) Flights...">
<meta itemprop="description" content="Book Mumbai (BOM) to New Delhi...">
These Microdata tags duplicate the title and meta desc already declared as standard meta tags and JSON-LD.

CT fix: Remove the Microdata itemprop meta tags. Keep JSON-LD only — it's Google's preferred format and easier to maintain.

CSRF Token Exposed in HTML Meta Tag

Security Note

CT renders a live CSRF token directly in the page HTML: <meta name="csrf-token" content="/3zLzC8ajK7FnDb5LZN...">. While CSRF tokens in meta tags are a standard Rails pattern, this confirms the page is rendered server-side with session state. For SEO, this means Googlebot gets a unique CSRF token per crawl — ensure this doesn't trigger rate limiting or session tracking that could slow Googlebot's crawl budget.

Impact on crawlability

If CT's backend tracks CSRF token requests and applies any rate limiting or bot detection based on token usage, Googlebot's crawler could be inadvertently throttled. Monitor crawl rate in Search Console.

FAQ Prices Hardcoded — Stale Data Risk

High

CT's FAQ schema answer reads: "Average airfare runs around Rs.6958 to Rs.34959 depending on booking timing and travel season." The ₹6,958 figure is today's lowest fare — it will be wrong tomorrow. Stale price data in FAQ schema is an EEAT trustworthiness failure and can trigger misleading snippet penalties.

CT FAQ schema — hardcoded price

"text": "Average airfare runs around Rs.6958 to Rs.34959 depending on booking timing and travel season."
If tomorrow's lowest fare is ₹7,500 but the FAQ says ₹6,958, users who click expecting ₹6,958 will bounce — a CTR+bounce signal Google measures.

CT fix: Make FAQ price answers dynamic or use a range: "₹4,800 to ₹12,000 depending on booking window." Avoid specific prices in FAQs unless they update daily.

CT Has fetchpriority="high" — A Genuine Advantage

Positive Signal

CT uses the modern fetchpriority="high" attribute on above-the-fold content images — a Chrome 102+ performance feature that tells the browser to prioritise these fetches for LCP (Largest Contentful Paint). No competitor HTML shows this attribute. This is a Core Web Vitals advantage that directly impacts LCP score.

CT — correct fetchpriority usage

<img src="...price.webp" fetchpriority="high"/>
Good: prioritises hero/above-fold images for faster LCP. The irony: these images also have alt="placeholder" — fixing the alt text costs nothing and preserves this performance gain.

Internal Links Use "To" Capitalisation (Inconsistent)

Medium

CT's internal links use anchor text like "Mumbai To Goa Flights", "New Delhi To London Flight" — capitalising "To". Other links use "from" in lowercase. Inconsistent anchor text formatting is a minor quality signal but it also suggests templated generation where the "From/To" variable isn't normalised. More critically, anchor text "Mumbai To New delhi Flight" (lowercase 'd') appears in links — the same capitalisation bug propagated into link text.

Link 15: "New Delhi To Bangalore Flights" (capital T)
But heading: "Mumbai to New delhi Flights" (lowercase t, lowercase d)
The template inconsistency signals non-editorial, auto-generated content to quality raters.
